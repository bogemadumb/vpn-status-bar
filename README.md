# vpn-status-bar

Приложение для строки меню macOS: личный туннель и мониторинг соединения.
Показывает, жив ли туннель, где именно в цепочке Мак → роутер → провайдер → сервер → сайт появляется задержка,
не утекает ли трафик мимо туннеля, и управляет ключами собственного сервера.

Это личный инструмент: один Мак, один собственный VPS. Проект выложен как пример нативного macOS-приложения
с конечным автоматом состояний, привилегированным помощником и покрытием тестами.

## Зачем

Готовые VPN-клиенты показывают «подключено / не подключено» и больше ничего. Мне нужно было видеть причину:
упал ли сервер, тормозит ли канал до провайдера, пошёл ли DNS мимо туннеля. И хотелось, чтобы при обрыве
туннеля наружу ничего не уходило (kill switch).

## Стек

- Swift 6 (язык Swift 5 в сборке), SwiftUI + AppKit, без внешних зависимостей;
- sing-box на маке (клиентское ядро, управляется через его локальный API);
- xray на VPS (серверная сторона), небольшой админ-скрипт на Python 3;
- SQLite (история измерений), pf (kill switch), Keychain (секрет локального API), launchd.

## Возможности

- Щит в строке меню: зелёный, жёлтый (медленная сеть), красный (обрыв), серый (выключено). Горячая клавиша ⌥⌘V.
- Панель: состояние, скорость, пинг, график, режим маршрутизации (раздельный / всё через сервер / напрямую), тест скорости.
- «Где тормозит?» — пошаговая проверка цепочки до сайта с вердиктом одной строкой.
- Окно: обзор с графиками, живые соединения, правила маршрутизации, ключи сервера (QR, отзыв), журнал событий, настройки.
- Проверки утечек: IPv6, DNS, геопривязка выходного адреса.
- Сторож: следит за ядром, при зависании перезапускает, шлёт уведомления.
- Несколько выходов (свой сервер + внешние) с автовыбором и уведомлением о переключении.
- Карточка сервера: нагрузка, память, диск, аптайм, срок сертификата.

## Архитектура и решения

| Часть | Где | Решение |
|---|---|---|
| Состояния | `StateMachine.swift`, `StateModel.swift` | Конечный автомат: переходы описаны чистой функцией, поэтому покрыты тестами без UI и сети |
| Чистая логика | `*Logic.swift`, `RouteVerdict.swift`, `NetParse.swift` | Всё, что можно проверить без системы, отделено от вида и вынесено в файлы, которые собираются вместе с тестами |
| Ядро | `CoreClient.swift` | Общение с локальным API sing-box; секрет API читается из Keychain через `/usr/bin/security` |
| Привилегии | `system/vpn-ctl` | Приложение не root. Единственный привилегированный скрипт вызывается через `sudo -n` и умеет только `on/off/restart/show/apply/killswitch` |
| Применение конфига | `vpn-ctl apply` | Проверка `sing-box check`, бэкап, перезапуск, 25 секунд на подъём туннеля, иначе автоматический откат |
| Kill switch | `vpn-ctl killswitch` | pf-правила в подъякоре: при включённом VPN и упавшем туннеле наружу идёт только локальная сеть и адрес сервера |
| Сервер | `system/vps/` | Админ-скрипт на VPS вызывается по ssh-ключу с ограничением команд (`vpn-admin-ssh.sh` пропускает только белый список) |
| История | `History.swift` | SQLite, часовые и суточные агрегаты, 30 дней |
| Секреты | — | Ссылка с ключом живёт только в памяти, буфер обмена очищается через минуту; в репозитории нет ни адресов, ни ключей |

## Настройка под себя

Все адреса и имена вынесены из кода.

1. Скопируйте `config.example.json` в `~/Library/Application Support/VPNMonitor/config.json` и впишите свои значения:
   адрес сервера, пользователь и путь к ssh-ключу, код страны сервера, хост для проверки геопривязки, списки сайтов для проверок связи (`local_sites` и `external_sites`).
2. На маке создайте `/usr/local/etc/singbox/server.env` со строкой `SERVER_IP=<адрес вашего VPS>` (нужен для kill switch).
3. Установите `system/vpn-ctl` в `/usr/local/libexec/vpn-ctl` (владелец root) и разрешите его вызов через sudoers без пароля.
4. Секрет локального API sing-box положите в Keychain: сервис `dev.vpnstatusbar.clash`, аккаунт — ваше имя пользователя.
5. На VPS: `system/vps/vpn-admin.py` в `/usr/local/bin/vpn-admin`, имя хоста сервера — в `/etc/vpn-admin.host`,
   `vpn-admin-ssh.sh` как принудительная команда ssh-ключа (`command="..."` в `authorized_keys`), cron-запись из `cron-vpn-admin`.

Без `config.json` приложение запускается с адресами-заглушками из документационного диапазона (203.0.113.0/24).

## Сборка и тесты

Нужен macOS 13+ и Xcode Command Line Tools со Swift.

```
bash app/Tests/run.sh     # тесты логики, в конце RESULT passed=… failed=0
bash build.sh             # приложение в ./build/VPNMonitor.app, подпись ad-hoc
bash build.sh --install   # то же и копия в ~/Applications
```

Если в Command Line Tools несколько SDK и сборка падает на макросах SwiftUI, укажите SDK явно:
`SDK_PATH=/Library/Developer/CommandLineTools/SDKs/MacOSX26.sdk bash build.sh`.

Проверки из командной строки: `VPNMonitor --probe-leaks`, `--speedtest`, `--probe-route`, `--test-keys`,
`--snapshot-stage789 <папка>` (скриншоты всех экранов в светлой и тёмной теме на тестовых данных).

## Ограничения

Это личный проект: протестирован на одной конфигурации (Apple Silicon, macOS 26). Сборка только под arm64.
Перезапуск ядра или xray рвёт активные соединения — приложение просит подтверждения перед такими действиями.
